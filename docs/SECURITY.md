# Границы безопасности Part 2

API закрыт по умолчанию. Роли ограничены БД; создание OTP-пользователя всегда client, назначение роли не даёт staff. Управление пользователями и юридическими документами — только superuser. Пользователь видит только собственные сессии и согласия. UUID не заменяет object permissions.

OTP хранятся как HMAC с секретом и challenge UUID, проверяются constant-time, одноразовы и ограничены попытками/сроком. В production коды не выводятся в API или приложение-логи. Console email выводит их только в режиме локальной разработки. Реестр refresh хранит HMAC jti, а не полный токен; rotation, replay и отзыв проверяются сервером.

Квоты OTP/email/IP/global хранятся в общей БД, а общие DRF throttles пока используют per-process cache и служат дополнительной защитой. Эти ограничения не заменяют внешний DDoS-фильтр. Не доверяем произвольному X-Forwarded-For: настройку доверенного proxy/IP нужно завершить до размещения (AUTH.md).

Production требует PostgreSQL, сильный секрет, точные hosts, HTTPS origins и secure cookies. API no-store; unexpected errors не возвращают exception text; OTP delivery log не содержит SMTP credentials или адреса. Для будущих логов/мониторинга исключить request bodies с кодами/токенами и персональными данными. Admin password login ещё не имеет 2FA/lockout: до защиты оставить доступ локальным либо через VPN/IP allowlist.

Не хранить `.env`, базы, реальные документы и токены в Git. Не раздавать private_media как static. В этом архиве нет endpoint для загрузки удостоверений или приёма оплаты. До реального запуска ещё нужны резервные копии, мониторинг, проверка SMTP, PostgreSQL-нагрузки, инфраструктуры и восстановление данных.

Черновики соглашений разрешены только local/test. Production блокирует вход по OTP без юридического имени ИП и опубликованных документов. Email verification, принятие соглашения и декларация 18+ — разные события; декларация не проверяет документ или действительный возраст. Финальные тексты, основания обработки, права других собственников, сроки хранения и удаление аккаунта требуют отдельной реализации до запуска с клиентами. Обязательные сроки хранения не выдуманы.

Планируется размещение базы и документов в Казахстане; Gemini пока не подключён. Передача данных AI требует отдельного решения, минимизации и согласий. Part 2 не разрешает передачу документов в сторонний AI.

Подробные сроки и устройство авторизации — AUTH.md. Локальные результаты и непроверенные интеграции — VALIDATION.md.
