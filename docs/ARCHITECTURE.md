# Архитектура Part 2

Проект — модульный Django-монолит. Отдельные микросервисы для этой стадии не требуются.

| Путь | Ответственность |
|---|---|
| `config/settings/base.py` | Общая конфигурация, DRF, языки, timezone |
| `config/settings/local.py` | Локальная разработка, SQLite по умолчанию, DEBUG |
| `config/settings/test.py` | Изолированная тестовая БД и тестовый хешер |
| `config/settings/production.py` | PostgreSQL, HTTPS, строгие параметры запуска |
| `apps/accounts/` | Пользователи, роли, admin, OTP, квоты, JWT-сессии, профиль |
| `apps/legal/` | Версии документов и история согласий |
| `apps/core/` | Системные API, конфигурация, ошибки, request ID |
| `docs/openapi.yaml` | Машиночитаемый API текущего Part |
| `scripts/init_env.py` | Безопасное первоначальное создание локальной `.env` |

Новые предметные модули (услуги, заявки, документы, оплаты, расписание, уведомления, AI) добавляются по мере реализации. Пустые заглушки API, возвращающие фиктивный успех, не создаются.

## Пользователь

UUID; email вместо username; имя/фамилия; необязательный телефон E.164; язык ru/kk/en; роль; флаги активности и технического доступа; дата подтверждения email; даты создания/обновления/входа. ИИН и документы не хранятся в Part 1.

Email целиком приводится к нижнему регистру — это осознанная политика проекта. Уникальность Lower(email) защищена индексом БД даже при обходе менеджера. Поле email также имеет обычную уникальность для совместимости Django auth.

| Роль | Будущее назначение | Django Admin в Part 1 |
|---|---|---|
| client | Собственные объекты/заказы/документы | Нет |
| appraiser | Обработка заявок, осмотры, отчёты | Нет |
| admin | Управление системой | Только при is_staff; управление аккаунтами — только суперпользователь |

`createsuperuser` создаёт активного admin + staff + superuser. Изменение role не включает staff автоматически. Ограничения БД запрещают staff у client/appraiser и superuser без staff/admin. Неактивный пользователь не аутентифицируется.

Ролевые permission-классы не заменяют проверку владельца объекта. Она обязательна при добавлении заявок и документов. Удаление пользователей из Django Admin пока запрещено; для отключения используется is_active=False. Политика удаления/обязательного хранения добавится отдельно.

## API и клиенты

URL-префикс `/api/v1/`, завершающий слеш, JSON, snake_case. UUID передаются строками. Времена — ISO 8601 с timezone; хранение времени с USE_TZ=True, локальная зона Asia/Almaty. В будущих денежных API использовать decimal-строки или целые тиыны, не float.

По умолчанию API требует аутентификации. Публичность каждого системного маршрута задана явно. В Part 2 работает Bearer JWT с серверным реестром сессий; Django session сохранена для admin и браузерной проверки профиля (CSRF сохраняется). API /me доступен администратору после входа в браузере, но архитектура подходит для любого аутентифицированного пользователя.

Production-схема и Swagger доступны staff; local — публичны. Swagger assets поставляются пакетом sidecar, поэтому интерфейс не зависит от CDN.

Контактные данные исходят из подтверждений владельца. legal_name=null, пока юридическое название не предоставлено; домен ocenka360.com не считается зарегистрированным или развёрнутым.
